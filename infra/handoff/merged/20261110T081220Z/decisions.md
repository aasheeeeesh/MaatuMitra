### D-?: A flag the reviewer confirmed must count as "resolved" when saving   (Phase B / m5_backend + m6_ui / orchestrator / 2026-11-10)
- What we needed to decide: The UI (m6) lets a reviewer answer each flag with "Yes, this is correct" or by editing the field. But the server (m5) refuses to save any record whose verdict still contains a flag. So a record where the reviewer looked at a flag and confirmed it can never be saved. Who is right?
- Options we considered: (1) Keep the server as it is. Pro: strictest. Con: the reviewer must invent an edit to get past a flag that was actually fine; that teaches people to make pointless edits and breaks the brief's "confirmed OR edited" rule. (2) The save request carries a list of resolutions (which check, which field, "confirmed" or "edited", by whom). The server accepts the save only if EVERY flag in the latest verdict has a matching resolution from the approving physician, and writes each one to the audit log. Pro: matches the brief; every override leaves a trace. Con: needs a change in m5's API and tests. (3) Let the UI drop flags before saving. Pro: easy. Con: the UI could be bypassed; the safety rule must live on the server.
- What we chose: Option 2, to be built in the next m5 fix pass (after the security audit). This is an API change, not a contract change: record.v1 and verdict.v1 stay the same.
- Why: The brief says Approve unlocks when every flagged field is "individually confirmed or edited", and that the server enforces the gate. A confirmed flag is a human decision, so it must be allowed and recorded, not hidden.
- What we actually did: Logged it in m6_ui/handoff/open_questions.md (by the m6 builder) and here. Until it is built, the UI shows the server's refusal honestly ("NOT saved").
- What could go wrong / weaknesses: Reviewers may click "confirm" without really checking (automation bias). The E7 user-study kit is designed to measure exactly this.
- What else could be done: Require a short reason or a "play the audio" step before a critical flag can be confirmed.
- How to change this decision later: m5_backend save endpoint and its tests; m6_ui gate client.
- Status: not done (planned for the m5 fix pass)
