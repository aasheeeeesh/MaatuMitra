### D-?: The extractor builder saw one template file that also contains a test family   (Phase B / m3_extract / orchestrator / 2026-11-10)
- What we needed to decide: The m3 builder reported that, while reading templates to learn the phrasing, it opened data/templates/a_asha_fever_cough.yaml, which also holds the sentence frames of a TEST family (a_fever_cough__f3). It did not open any test gold or test transcript. Does this break the frozen-test rule, and what do we do?
- Options we considered: (1) Ignore it. Pro: no work. Con: hides a possible leak; dishonest. (2) Throw away m3 and rebuild it without template access. Pro: cleanest. Con: costs a lot of usage; the builder still needs to know the general phrasing from somewhere. (3) Keep m3, disclose the exposure, and have the integrity auditor check whether any rule or phrase list in m3 matches wording that appears ONLY in test families. If a test-only phrase is found, remove it and re-score dev. Pro: proportionate; makes the risk measurable. Con: a subtle influence (for example word order ideas) cannot be fully ruled out.
- What we chose: Option 3.
- Why: Template files are not gold labels, and the leak is limited to one family's sentence frames. The honest fix is to disclose it and check for test-only wording, then report the test score of that family separately so a reader can see whether it looks suspiciously good.
- What we actually did: Checked that no test conversation id appears anywhere in results/m3_extract (0 found) and that the test lock is intact (`mingw32-make split-lock` -> OK). Added this check to the integrity auditor's job list. Also recorded the builder's honest dev-score caveat: 240 dev conversations were used to write the rules (in-sample, 0 critical errors), and 88 held-out dev conversations are the fair estimate for new wording; that holdout is no longer clean after the v2 fix (v1 scores kept in results/m3_extract/rules_v1_frozen/).
- What could go wrong / weaknesses: The test score for the a_fever_cough__f3 family may be optimistic. The in-sample dev score (0 critical) must never be quoted as the system's accuracy.
- What else could be done: Future builders get a template view with test families removed (a filtered copy), so they cannot see test frames at all.
- How to change this decision later: m1_data could publish data/templates_dev_only/; m7 should report the a_fever_cough__f3 family separately in E2/E3 test results.
- Status: partly done (auditor check pending)
