### D-?: Clinical review of m1 and m4, and one planned refreeze of the test split (REFREEZE-1)   (Phase B / m1_data, m4_verify / orchestrator / 2026-11-10)
- What we needed to decide: The simulated clinical reviewer (reviews/m1_data/2026-11-10-clinical.md and reviews/m4_verify/2026-11-10-clinical.md, label ai_simulated_review) found two CRITICAL problems: (1) five templates (a3, e8, h2, h3, i5) show a child ("ಮಗುವಿಗೆ") being given ADULT doses (paracetamol 1000 mg or 2 tablets up to 4 times a day; ibuprofen 400 mg); (2) the verifier's dose check C4 uses adult ranges for everyone, so it lets those child doses pass. Two of these templates (h2, h3: 16 conversations) are in the FROZEN test split. Do we change frozen test data?
- Options we considered: (1) Keep the data as it is and only fix C4. Pro: the test lock is untouched. Con: our "gold" (correct answer) data would keep teaching that an adult dose for a child is a normal record; a reader could copy unsafe example sentences; and every correct C4 flag on those fields would wrongly count as "review burden". (2) Do ONE documented refreeze now, before any test-split run: fix the child templates (child turns get no dose or a paediatric liquid in ml with an age band), fix the lexicon rows the reviewer corrected, then regenerate and relock. Pro: the data stops showing unsafe dosing; the scores measure the verifier, not our own data mistakes. Con: the lock changes once; we must show in git that no test result existed before the change. (3) Delete the child templates. Pro: simple. Con: loses the child/paediatric case, which is exactly where real dosing danger is.
- What we chose: Option 2, called REFREEZE-1. It will be done by the m1 fix pass AFTER the Kannada review of the templates, so that the test data changes only once.
- Why: The brief forbids tuning on test and changing test data after evaluation. It does not forbid fixing a clinically unsafe data error before ANY test evaluation has happened (D-64 allows a documented refreeze before the first `make eval-test`). results/test_access_log.md shows no test run yet. Fixing data safety beats keeping an early lock.
- What we actually did: Validated both clinical reports against review_report.v1 (the reviewer had no shell): both valid. Accepted findings (to fix in the m1 and m4 fix passes): paracetamol range 1000-1000 -> 500-1000 mg and max daily 3000 -> 4000 mg (NHS page fetched by the reviewer); ondansetron 8-24 -> 4-24; metformin 500-850 -> 500-1000; ibuprofen 300-800 -> 200-800 (openFDA labels fetched by the reviewer); ORS needs a unit (sachet or ml); iron-folic acid needs per-component units; add the "625" alias for amoxicillin-clavulanate; remove the "levo" alias (it often means levocetirizine; reviewer judgement only); template e2 must not say ciprofloxacin can be taken together with zinc or iron; C4 must treat doses for a child as "not checkable" (flag); C4's "blank range" flag gets its own reason code ("cannot verify") and is reported separately, so scores measure the verifier and not gaps in our drug list; add max_daily where a fetched source gives it; restrict allowed units per drug; E4 drug swaps must pick confusable drugs from the lexicon; docs/severity.md gets new critical classes for route, child/weight-based dose and liquid strength (a pre-registration document change, logged before any test run). DEFERRED (UNVERIFIED, human must check): metronidazole 200-2000 and cotrimoxazole 400-800 (not re-fetched); all NLEM rows (every NLEM PDF fetch failed); ISMP confusable pairs (PDF unreadable); the AWaRe edition year. Confirmed correct: the AWaRe class of all 18 antibiotics on the WHO portal.
- What could go wrong / weaknesses: A refreeze can look like moving the goalposts. Mitigation: it happens before any test result exists, it is one commit with this entry in the message, and the old lock stays in git history. The reviewer is simulated, not a real clinician: the clinical sheet (reviews/human_sheets/clinical_review_sheet.csv, 34 drugs + 13 findings) must still go to a real pharmacist or doctor.
- What else could be done: Add a paediatric weight-based dose table from a fetched national source (for example the IAP or NLEM paediatric doses) so C4 can really check child doses instead of only flagging them.
- How to change this decision later: data/templates/{a,e,h,i}_*.yaml, data/lexicon/drugs.csv, m4_verify C4 config, docs/severity.md; regenerate with `mingw32-make data` and relock in ONE commit.
